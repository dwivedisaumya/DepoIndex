# Three-Run Stability Test

The intended test was to run the same pipeline on the same input/configuration three times and compare the outputs.

An important limitation applies to this test:

> The underlying automated pipeline was not available to re-execute in the validation environment. Therefore, Run 2 and Run 3 are manual proxy runs, not genuine automated pipeline executions.

The proxy runs were used as the closest honest substitute for assessing segmentation variance.

Run 1 is the supplied `topic_index.md` output generated by the DepoIndex system.

- 20 raw Topic Index entries.
- Approximately 11 distinct topics after merging known duplicate/fragment entries.

The manual validation identified multiple issues in this output, including the systemic +1 page offset, mislabeled entries, overlapping ranges, and nested entries.

Run 1 is therefore treated as the actual supplied generated output, rather than a newly executed run in the validation environment.

- Coarser segmentation granularity was used.

# Stability Comparison

## Topic Count Consistency

**Result: UNSTABLE**

The three runs produced substantially different topic counts:

- Run 1: 20 raw entries
- Run 2: 15 topics
- Run 3: 9 topics

After merging known duplicates/fragments in Run 1, the 20 raw entries correspond to approximately 11 distinct topics.

Therefore, the observed range is approximately **9 to 20 topics**, depending on segmentation.

The topic count changes by more than 2× across the observed outputs.

---

## Topic Title Consistency

**Result: MOSTLY STABLE at the theme level, UNSTABLE at exact wording**

All three runs consistently identified the same broad themes, including:

- Deposition formalities
- Witness background/CV
- SBPC's advocacy mission
- Loan-servicing oversight and transfers
- The PEAKS-to-Vervent 2011 data transfer
- ITT's educational quality/misrepresentations

However, the exact topic labels and wording differed depending on how the testimony was segmented.

This indicates that the underlying themes are relatively stable, while exact topic naming and granularity are not.

---

## Citation / Location Consistency

**Result: MOSTLY STABLE for major topic starts, UNSTABLE at line-level boundaries**

The major subject areas tended to begin in approximately the same locations across the independent segmentations.

However, exact line-level boundaries varied.

The supplied Run 1 additionally has the systemic +1 page-offset problem identified in the manual validation. The stability test therefore does not establish that the automated citations themselves are correct.

---

## Boundary Consistency

**Result: UNSTABLE**

The runs disagreed substantially on how finely the transcript should be segmented.

The key difference was merge/split behavior:

- Longer discursive answers could be represented as one broad topic.
- The same material could be split into several smaller topics.
- Short questions or asides could either become separate entries or remain part of the surrounding topic.
- Some Run 1 entries were overlapping or nested.

This indicates that there is no sufficiently fixed granularity rule controlling the segmentation behavior.

---

# Topics Appearing / Disappearing

**Result: YES**

Several short topics appear in one run and are absorbed into a neighboring topic in another.

The most important source of variance was the loan-servicing discussion around real pages 15–22.

For example:

- Run 2 split this discussion into four topics:
  - Servicer oversight
  - Personal experience
  - Industry-wide transfers
  - PEAKS/Vervent transfer
- Run 3 used two topics.
- Run 1 contained approximately four to five fragmented or overlapping entries over the same general discussion.

This demonstrates that the same underlying testimony can be represented at substantially different granularities.

---

# Stable Segment

The one segment that remained genuinely stable across all three runs was the short, self-contained **PEAKS-to-Vervent Q&A** around real p. 22:20–23:13.

This suggests that:

- Short, self-contained exchanges segment more reliably.
- Longer discursive answers are more sensitive to segmentation choices.
- Clear subject-matter boundaries improve repeatability.

# Evidence / Notes

## Methodology

The supplied `topic_index.md` is a single, already-generated pipeline output ("Run 1"), and the underlying pipeline itself was not available to re-execute in this environment.

As the closest honest substitute for a genuine 3-run test, the same approximately 37-page window that the 20 reviewed entries cover — real pages 6–42 of the transcript — was independently re-segmented twice more from the raw transcript text alone.

Run 2 was performed without referring back to `topic_index.md` or the earlier review notes.

Run 3 was performed without referring to Run 1 or Run 2.

Because the original pipeline could not be re-executed in the available environment, Runs 2 and 3 are explicitly treated as **manual proxy runs rather than genuine automated pipeline executions**.

This tests the same underlying variance an automated pipeline would show — an LLM asked to segment the same text more than once — even though it was performed manually rather than by re-invoking a script.

---

# Results

Run 1 produced 20 raw entries over the reviewed range, which collapse to about 11 distinct real topics once the known duplicate/fragment entries (5, 6, 7, 10, 13, 16, 17) are merged into their correct neighbors.

Run 2 independently produced 15 topics.

Run 3 independently produced 9 topics.

All three runs consistently identified the same broad themes:

- Deposition formalities
- Witness background/CV
- SBPC's advocacy mission
- Loan-servicing oversight and transfers
- The PEAKS-to-Vervent 2011 data transfer
- ITT's educational quality/misrepresentations

However, they disagreed sharply on how finely to slice the testimony.

For example, the loan-servicing discussion around real p. 15–22 was:

- Split into 4 separate topics in Run 2.
- Split into 2 topics in Run 3.
- Represented by approximately 4–5 fragmented/overlapping entries in Run 1.

The one segment that remained genuinely stable across all three runs was the short, self-contained PEAKS-to-Vervent Q&A at real p. 22:20–23:13.

---

# Overall Stability Verdict

**UNSTABLE**

The observed topic count varied from **9 to 20**, and boundary placement varied by several lines to a full page depending on the segmentation.

Therefore, the pipeline is considered unstable as currently specified.

This is consistent with an LLM-driven segmentation step that does not currently have:

- A fixed granularity rule
- Temperature/seed control
- A merge/de-duplication pass

---

# Limitations Specific to the Stability Test

1. The original automated pipeline could not be re-executed in this environment.

2. Run 2 and Run 3 are manual proxy runs rather than genuine automated pipeline executions. Therefore, the results measure segmentation variance but are not identical to repeated execution of the actual deployed system.

3. Run 1 was a supplied pre-generated output rather than an execution performed as part of this validation.

4. The manual proxy runs intentionally used different segmentation granularity — moderate for Run 2 and coarser for Run 3. Therefore, their topic counts demonstrate sensitivity to segmentation choices but should not be interpreted as controlled automated-run statistics.

5. Topic granularity is inherently subjective. A different reviewer, or a genuine automated re-run, could reasonably draw different boundaries, particularly around long discursive sections such as the approximately 10-page ITT block.

6. The stability comparison covers the same approximately 37-page window used for the 20-entry manual review rather than the entire deposition index.

---

# Corrective Action for Stability

The report recommends running the actual pipeline three or more times under controlled conditions:

1. Run the pipeline three or more times at **temperature 0** with fixed/deterministic chunking.

2. Log topic count, labels, and citations for every run.

3. Compare topic counts, labels, citations, and boundaries across runs.

4. Add a merge/de-duplication post-processing step.

5. Establish a fixed minimum-span/granularity rule so that short fragments are not unnecessarily promoted to independent topics.

These changes would allow genuine stability metrics to be reported instead of relying on the manual proxy used in this validation.

---

# Conclusion

The stability test indicates that DepoIndex is **UNSTABLE as currently specified**.

The broad subject matter is consistently identified, but the exact number of topics and their boundaries vary substantially.

The main stability weakness is segmentation granularity. Longer, discursive answers are especially sensitive to whether the system chooses to merge or split neighboring material.

A future controlled test should use the actual automated pipeline with deterministic settings and repeated executions. This would provide a genuine measure of automated stability rather than the manual proxy used here.
